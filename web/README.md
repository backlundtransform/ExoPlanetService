# ExoplanetHunter web and Android app

Interactive 3D star map and exoplanet systems, built with React, Three.js
(@react-three/fiber) and Vite. The same code is published in two ways:

| Target | Build | Served from |
|---|---|---|
| Web (PWA) | `npm run build` | The API, at `https://exoplanethunter.com/astro3d/`. Output goes to `../src/ExoplanetHunter.Api/wwwroot/astro3d/` |
| Android | `npm run build:android` | The Capacitor app `com.varoid.exoplanethunter` in `android/` |

The app was moved here from
[ExoplanetHunter-Astro3D](https://github.com/backlundtransform/ExoplanetHunter-Astro3D),
which keeps its earlier history.

## Development

```bash
npm install
npm run dev        # http://localhost:5173/astro3d/
```

The dev server proxies `/api` to a local API on `http://localhost:5099`. Start the API from
the repository root:

```bash
dotnet run --project src/ExoplanetHunter.Api --urls http://localhost:5099
```

To use production data instead, start the dev server with
`VITE_API_PROXY=https://exoplanethunter.com npm run dev`.

`npm run lint` and `npm run build` must pass before merging. CI runs both.

## Routes

| Path | View |
|---|---|
| `/astro3d/` | Star map with a searchable star list |
| `/astro3d/star/{id}` | 3D view of one star system. The link can be shared |

## PWA

`vite-plugin-pwa` generates the manifest and a service worker:

- The app shell is precached.
- API responses use stale-while-revalidate, so the app opens instantly and works offline.
- Planet textures are cached the first time a system is opened.

The service worker updates itself automatically on the next visit after a deployment.

## Android

```bash
npm run build:android    # builds with base "/" and runs `cap sync android`
npx cap open android     # opens Android Studio for signing and release builds
```

- The app calls the production API directly. With `CapacitorHttp` enabled in
  `capacitor.config.ts`, `fetch()` uses native HTTP and is not subject to CORS.
- On Android, the 📡 button points the star map where the phone is aimed, using GPS and the
  device orientation sensors.

## Assets

Planet textures are WebP in `public/textures`, named `{zone}_{massClass}_{composition}.webp`
(see `src/textures.ts`). PWA icons are in `public/icons`. Both are generated by
`python tools/web/optimize_images.py`.

## Translations

The UI text is in `src/i18n/<language>.json`. Every file in that folder is loaded
automatically. A key missing from a language falls back to English.
